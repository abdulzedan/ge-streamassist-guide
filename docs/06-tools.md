# 6. Tools (`toolsSpec`)

Four tools can be attached per request. Each spec is enabled by *presence* —
three of them are empty objects.

```json
"toolsSpec": {
  "webGroundingSpec":    {},
  "vertexAiSearchSpec":  { ... },
  "imageGenerationSpec": {},
  "videoGenerationSpec": {}
}
```

## Web grounding

```json
"toolsSpec": { "webGroundingSpec": {} }
```

- Requires the assistant-level setting `webGroundingType` to be
  `WEB_GROUNDING_TYPE_GOOGLE_SEARCH` or `WEB_GROUNDING_TYPE_ENTERPRISE_WEB_SEARCH`
  — check with [`22-get-assistant.sh`](../snippets/curl/22-get-assistant.sh).
  If it's disabled at the assistant level, the spec silently does nothing.
- Grounded fragments arrive with `textGroundingMetadata`
  (`references[].documentMetadata.uri/title/domain`, plus per-segment
  `groundingScore`). URIs are Google redirect URLs; `domain` holds the real
  site.
- Snippet: [`11-web-grounding.sh`](../snippets/curl/11-web-grounding.sh);
  captured output: [`outputs/11-web-grounding.excerpt.json`](../outputs/11-web-grounding.excerpt.json).

## Data store grounding (Vertex AI Search)

```json
"toolsSpec": {
  "vertexAiSearchSpec": {
    "dataStoreSpecs": [
      {
        "dataStore": "projects/{PROJECT_NUMBER}/locations/global/collections/default_collection/dataStores/{DATA_STORE_ID}",
        "filter": "category: ANY(\"reports\")",
        "numResults": 10,
        "boostSpec": {
          "conditionBoostSpecs": [
            { "condition": "document_id: ANY(\"doc_1\")", "boost": 0.8 }
          ]
        }
      }
    ]
  }
}
```

- Restricts retrieval to the listed stores — only meaningful on apps with
  multiple data stores; omit the spec to search all of them.
- The `dataStore` path officially requires the **project number** (ID has been
  observed to work; don't rely on it).
- `filter` uses Vertex AI Search filter syntax against your schema's
  indexable/filterable fields; an unparseable filter fails the request with
  `INVALID_ARGUMENT`.
- `boostSpec` supports condition boosts (−1..1) and curve-based
  `boostControlSpec` (NUMERICAL / FRESHNESS attributes).
- Workspace-backed stores (Drive/Gmail/Calendar) additionally accept
  `customSearchOperators`.
- Snippet: [`12-datastore-grounding.sh`](../snippets/curl/12-datastore-grounding.sh).

## Image generation

```json
"toolsSpec": { "imageGenerationSpec": {} }
```

The image is **not returned inline**. You get a reply whose content is
`{"file": {"fileId": "…", "mimeType": "image/png"}}` (and a short text like
"Image generated by …"). The bytes live in the session's context files —
download with `:downloadFile` ([08-files.md](08-files.md), snippet 17).
Captured output: [`outputs/13-image-generation.json`](../outputs/13-image-generation.json).

## Video generation

```json
"toolsSpec": { "videoGenerationSpec": {} }
```

Identical pattern: reply carries `{"file": {"fileId": "…", "mimeType":
"video/mp4"}}`. Generation can take a minute or more — keep the HTTP stream
open (snippet 14 raises curl's `--max-time`).

## Notes

- Tool selection is still model-driven: enabling a spec makes the tool
  *available*; a prompt that doesn't call for it won't use it.
- The deprecated top-level fields (`googleSearchGroundingEnabled`,
  `webGroundingEnabled`, top-level `dataStoreSpecs`) still appear in older
  examples — use `toolsSpec` exclusively.
- Generated media lives inside the session that produced it; files are only
  addressable through that session (there is no global file API).
