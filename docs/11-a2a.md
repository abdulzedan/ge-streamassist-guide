# 11. Registry A2A invocation

An agent can be called through A2A only when its Agent Registry record
advertises an active `A2A_AGENT` protocol. Registration in a Gemini Enterprise
app by itself is not enough.

The Discovery Engine proxy URL uses the project number. Prefer the endpoint URL
returned by Agent Registry. Snippets 23 and 24 build the equivalent proxy path
for an agent attached to the configured app.

Required access:

- `roles/agentregistry.viewer` to discover the registry endpoint;
- `discoveryengine.assistants.assist` to invoke it;
- the `cloud-platform` OAuth scope and quota-project header.

## card

```text
GET {a2a-endpoint}/v1/card
```

Use that exact path. A non-A2A agent returns `501 UNIMPLEMENTED`.

## message

```text
POST {a2a-endpoint}/v1/message:stream
```

```json
{
  "message": {
    "role": "ROLE_USER",
    "content": [{"text": "Audit this package."}],
    "messageId": "unique-id"
  }
}
```

`ROLE_USER`, `content[]` and `messageId` are required. The stream is a JSON
array. Append `message.content[].text` and inspect `message.metadata`.

A successful terminal response may contain no text when the agent needs OAuth
or user confirmation. Handle `requiredAuthorizations`, `agentInvocation` and
`structuredData.required_authorization`. Send the handoff to the user; do not
log authorization URLs or their state parameters.

The live check found working A2A cards for Agent Designer, ADK and registered
A2A agents. Deep Research did not advertise A2A and returned the documented
unsupported-agent errors.
